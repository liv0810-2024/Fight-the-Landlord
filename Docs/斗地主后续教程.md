# Unity 斗地主学习路线

这是一套根据当前工程制定的循序渐进教程。目标不是让你直接复制一份成品，而是让你在写完每一个小模块后，能够解释：数据放在哪里、谁修改数据、为什么要有这个方法、出错时应该从哪里查。

你现在已经有卡牌数据、JSON、发牌、对象池、牌型识别、基础 UI、DOTween 和几个管理器。下面的课程会在这些代码上继续，不推倒重来。

## 总目标：做出一局完整可玩的单机斗地主

最终流程是：

```text
大厅
  -> 开始游戏
  -> 生成并洗牌
  -> 三人各 17 张，留下 3 张底牌
  -> 三人轮流叫分
  -> 确定地主并发放底牌
  -> 地主先出牌
  -> 玩家和两个 AI 轮流出牌
  -> 牌型校验、压牌、过牌
  -> 某一方手牌为空
  -> 倍数结算、金币变化
  -> 保存数据
  -> 显示结算面板并重新开始
```

第一版暂时不做联网、商城和复杂战斗特效。先完成可重复游玩的单机闭环，再增加工程化内容。

## 课程学习方式

每一课都按下面的顺序进行：

1. 先读需求，明确这一课解决哪个问题。
2. 画出数据流，回答“谁拥有数据、谁可以修改数据”。
3. 只写方法名、字段和伪代码。
4. 自己实现并运行最小测试。
5. 把代码发给我，我先帮你做代码检查。
6. 你理解之后，我再给这一课的完整参考代码。

不要一次性把所有脚本复制进去。初学者真正要练的是拆问题和验证假设。

## 第 0 课：认识现有工程和运行链路

### 这一课要做什么

从 `GameScene` 开始运行，确认你能看到：发牌、玩家手牌、两个 AI 的牌背、抢地主面板、出牌面板和结算面板。

### 重点理解

当前主要类的职责：

| 类 | 应该负责什么 |
|---|---|
| `CardData` | 一张牌的纯数据 |
| `Card` | 一张牌的场景表现和点击选择 |
| `DeckManager` | 牌堆、洗牌、发牌、手牌数据 |
| `CardRules` | 识别牌型和判断能否压牌 |
| `LandlordManager` | 叫地主和地主身份 |
| `PlayCardManager` | 出牌回合和上一手牌 |
| `CardLayoutManager` | 把数据画到屏幕上 |
| `GameMainManager` | 控制大阶段切换 |

### 你要问自己的问题

- `CardData` 为什么不继承 `MonoBehaviour`？
- 为什么 `Card` 不能代替 `CardData`？
- 为什么出牌规则不应该写在按钮脚本里？
- 一个阶段结束时，应该通过直接调用还是事件通知其他模块？

### 验收标准

你能画出下面的调用链，并说清楚每一步修改了什么：

```text
GameMainManager.StartGame
  -> DeckManager.DealCards
  -> Game_DealCardFinish
  -> CardLayoutManager.OnDealFinish
```

## 第 1 课：统一玩家和手牌的映射

这是现在最先要做的修复。

### 当前问题

`PlayCardManager.GetHandByTurn(0)` 目前返回了右 AI 手牌。玩家出完牌时，检查到的不是玩家自己的手牌。

### 这一课要做什么

建立唯一的玩家索引规则：

```text
0 = 玩家
1 = 左 AI
2 = 右 AI
```

### 建议的字段和方法

```csharp
private int currentTurn;
private List<CardData> GetHandByPlayerIndex(int playerIndex);
private string GetPlayerName(int playerIndex);
```

### 先思考再写

方法的伪代码：

```text
GetHandByPlayerIndex(playerIndex)
    如果是 0，返回 DeckManager.myHand
    如果是 1，返回 DeckManager.leftHand
    如果是 2，返回 DeckManager.rightHand
    其他值打印错误并返回 null
```

### 自己动手

修改 `GetHandByTurn`，把参数名改成 `playerIndex`。再在胜利检查处打印玩家索引和手牌数量。

### 验收标准

`CheckWin(0)` 检查 `myHand`，`CheckWin(1)` 检查 `leftHand`，`CheckWin(2)` 检查 `rightHand`。

这一课我会重点检查你的命名、非法索引处理和空引用风险。

## 第 2 课：把出牌动作拆成“检查”和“执行”

### 这一课要做什么

让玩家出牌流程变成固定顺序：

```text
收集选择
  -> 检查是否轮到玩家
  -> 检查是否为空
  -> 检查牌型
  -> 检查能否压牌
  -> 修改手牌
  -> 刷新画面
  -> 检查胜利
  -> 推进回合
```

### 建议的方法

```csharp
private List<CardData> CollectSelectedCards();
private bool ValidatePlay(List<CardData> selectedCards);
private void ExecutePlay(int playerIndex, List<CardData> playedCards);
private bool CheckWin(int playerIndex);
```

### 先思考

为什么不能在 `OnClickPlay` 里直接 `myHand.Remove`？

因为 UI 只知道“用户点击了按钮”，不知道牌型是否合法。规则判断和数据修改必须由流程管理器统一负责。

### 验收标准

- 选中非法牌时，手牌数据不改变。
- 压牌失败时，手牌数据不改变。
- 出牌成功后，数据和画面数量一致。
- 玩家手牌为 0 时不再启动下一个 AI 回合。

## 第 3 课：设计真正的叫地主流程

### 这一课要做什么

把现在的“玩家点一次就确定地主”改成三人轮流叫分。

叫分值建议使用 `0、1、2、3`，其中 `0` 表示不叫。

### 需要保存的状态

```csharp
private int currentBidder;
private int highestBid;
private int highestBidder;
private int bidCount;
private bool isBidding;
```

### 建议的方法

```csharp
public void StartBidding(int firstPlayer);
public void PlayerChooseBid(int score);
private void ChooseBid(int playerIndex, int score);
private int DecideAIBid(List<CardData> hand);
private void FinishBidding();
private void AssignBottomCards(int landlordIndex);
```

### 先画流程

```text
StartBidding
  -> 设置当前叫分者
  -> 如果是 AI，延迟后自动叫分
  -> 如果是玩家，打开 UI 等待点击
  -> 校验叫分
  -> 记录最高分和最高叫分者
  -> 下一个人
  -> 三人完成后确定地主
```

### 关键思考

玩家和 AI 不应该各自写一套“确定地主”的代码。玩家按钮和 AI 协程最后都调用同一个 `ChooseBid`，这样规则只有一份。

### 验收标准

- 三名玩家各有一次叫分机会。
- 最高叫分者拿到三张底牌。
- 没有人叫分时可以重新发牌。
- 地主索引正确传给 `GameMainManager`。

## 第 4 课：完善牌型识别和压牌规则

### 这一课要做什么

先保证规则正确，再让 AI 使用规则。

需要支持：

```text
单张、对子、三张、三带一、三带二
顺子、连对、飞机、炸弹、四带二、王炸
```

### 规则层的思考顺序

```text
输入：List<CardData>
  -> 按 weight 统计数量
  -> 判断牌型
  -> 计算主牌权重
  -> 和上一手牌比较
```

### 建议增加的结果数据

现在只返回 `CardType`，后续可以增加：

```csharp
public struct CardPattern
{
    public CardType Type;
    public int MainWeight;
    public int CardCount;
    public int BodyCount;
}
```

这样比较飞机、顺子和连对时，不需要重新猜测牌型信息。

### 必须测试的边界

- `10、J、Q、K、A、2` 不是顺子。
- 不同长度的顺子不能互相比较。
- 只有王炸能压王炸以外的所有牌。
- 普通牌不能压炸弹。
- 炸弹可以压普通牌。

### 验收标准

规则方法可以脱离场景对象运行。它不应该调用 `GameObject.Find`、UI 或动画。

## 第 5 课：设计回合、过牌和牌权

### 这一课要做什么

实现斗地主的核心牌权规则：

- 出牌成功后，当前牌成为上一手牌。
- 玩家可以选择过牌，但自由出牌时不能过。
- 连续两个人过牌后，上一手牌失效。
- 下一位玩家可以重新自由出牌。

### 状态字段

```csharp
private int currentTurn;
private List<CardData> lastPlayedCards;
private int lastPlayedPlayer;
private int passCount;
```

### 建议的方法

```csharp
private void AdvanceTurn();
private void PassTurn(int playerIndex);
private void ResetTrick();
private bool IsFreeTurn();
```

### 先思考

`AdvanceTurn` 只负责“换人”，还是也负责“清空上一手”？

建议分开：换人和重置牌权是两个不同动作。这样以后加托管、倒计时和网络同步时更清楚。

### 验收标准

完成这个序列：

```text
玩家出牌 -> 左 AI 过 -> 右 AI 过 -> 玩家重新自由出牌
```

## 第 6 课：先写一个能工作的 AI

### 这一课要做什么

第一版 AI 不追求聪明，只追求合法和稳定：

- 自由出牌时出最小可用牌。
- 跟单张时找最小可压牌。
- 跟对子时找最小可压对子。
- 没有能压的牌时过牌。
- 自己是先手时不能过牌。

### AI 方法

```csharp
private List<CardData> DecidePlay(List<CardData> hand, List<CardData> lastCards);
private List<CardData> FindSingleToBeat(...);
private List<CardData> FindPairToBeat(...);
private List<CardData> FindBombToBeat(...);
```

### 重要习惯

AI 返回的是 `List<CardData>`，不是直接调用 `Card.OnMouseDown()`。AI 是规则层的决策者，表现层只负责把结果画出来。

### 后续升级顺序

```text
单张
  -> 对子
  -> 三张
  -> 炸弹
  -> 顺子和连对
  -> 飞机
  -> 记牌和残局策略
```

### 验收标准

AI 不会出非法牌，不会在自由出牌时卡死，不会因为两个协程同时运行而连续出两次牌。

## 第 7 课：把 UI 接到状态，而不是接到临时按键

### 这一课要做什么

```csharp
private void RefreshButtons(GameState state, int currentPlayer);
```

你现有的 `UIManager` 是字典注册。下一步再增加栈：

```csharp
private Stack<BasePanel> panelStack;

public void PopPanel();
public void CloseAllPanels();
```

先保证所有面板能正确打开和关闭，再做层级栈，不要一次重构全部 UI。

## 第 8 课：状态机和游戏阶段

### 这一课要做什么

当叫地主和出牌流程能跑通后，再抽象状态机。

全局阶段：

```csharp
public enum GameState
{
    Idle,
    DealCard,
    Bidding,
    PlayCard,
    RoundOver
}
```

玩家内部状态：

```csharp
public interface IState
{
    void Enter();
    void Tick();
    void Exit();
}
```

### 方法设计

```csharp
public void ChangeState(IState nextState);
public void Tick();
```

### 为什么现在才学状态机

如果还没有理解叫地主和出牌的实际流程，过早抽象状态机只会增加类数量。先写出正确流程，再提取重复结构，才是适合初学者的学习方式。

### 验收标准

任何阶段不能执行其他阶段的按钮逻辑。例如叫地主阶段不能出牌，结算阶段不能继续出牌。

## 第 12 课：测试、低 GC 和打包

### 规则测试

先测试纯 C# 规则，不要一开始就通过点击场景测试所有情况：

```text
单张、对子、王炸、炸弹
顺子边界
不同长度顺子
连续过牌
玩家胜利
三人叫分
无人叫分重新发牌
```

### 性能检查

- 卡牌显示继续使用对象池。
- 场景初始化时缓存组件引用。
- 不要在每帧 `Find`。
- 避免在高频循环中反复创建临时字符串。
- 事件注册和注销必须成对出现。

### 打包验收

